# 横移、后退步态训练记录（Open Duck Mini v2，mjlab）

[English version](side_step_backward_gait_training.md)

2026-11-02 ~ 11-08。训练环境：mjlab + rsl_rl（Microduck 移植版），RTX 4060 笔记本，每次 4096 个并行环境。
规矩：**一次只改一处**，**每 1000 步考一次**（仿真考试 = `tools/mjlab_sim_check.py`：舵机 BAM 模型、IMU 延迟、齿隙、重心偏后 12 mm、摩擦 0.35 / 1.0 / 2.0、kp 20 / 25）。

## 一句话结论

光改奖励权重、指令范围、姿态约束，横移一直学不会；**把"动作要领"直接写成奖励规则**（摆动脚往指令方向挪就给分）后，第一次就学会了横移，后退也照此办法学会了。

## 起点

od17（当时装在真鸭上的模型）：前进、转弯稳定，但
- 横移：指令 ±0.15 m/s，实际 vy ≤ 0.04，基本原地踏步，还往前蹭；
- 后退：-0.15 指令只退 -0.03 ~ -0.06 m/s。

## 失败的尝试（都只改了一处）

| 版本 | 改动 | 结果 |
|---|---|---|
| od14 | 走路时髋侧摆姿态约束放宽（std 0.05 → 0.12） | 横移没变化 |
| od15 | 横移指令范围加大到 ±0.3（从 od13 接着练） | 后退、转弯退化，膝盖顶在限位上 38~98% 的时间 |
| od16 | 同上，从头练 | 根本不迈步，蹲着挪 |
| od20 | 膝盖力气 ×2.05（模拟 STS3046） | 训练中把后退练丢了，横移仍不会 |
| od21 | 速度跟踪奖励权重 ×2 | 0.15 的指令干脆站着不动 |
| od22 | od20 + 髋侧摆 std 0.12 | 能走，横移 vy 仍 ≤ 0.05 |
| od23 | 横移指令范围 ±0.25 | vy ±0.01，没改善 |

## 成功的做法：动作要领写成奖励

### od24：横移要领（用户的点子："告诉它怎么横移"）

`side_step_technique`：有横移指令（|vy| > 0.05）时，**每只在空中的脚**，按"离地以后在指令方向上挪了多远"给分（机身朝向坐标系里算），挪反方向扣同样的分；±4 cm 封顶，权重 1.0。抬脚高度由原有的抬脚奖励管。

结果（1000 步后，摩擦 1.0）：vy **+0.115 / -0.088**（指令 ±0.15），前进、转弯照常，没有摔倒。训练里"摆动脚侧移量"700 步内从 0.02 涨到 0.47。

### od25：后退要领（用户描述 + 人类后退步态研究：后退时步子要小）

`back_step_technique`：有后退指令（vx < -0.05）时，每只摆动脚按"离地后往后挪了多远"给分，**2.5 cm 给满分**，超过 4 cm 开始扣分（防止大步后退摔倒），权重 1.0。从 od24 第 19250 步接着练。

结果（od25 第 20500 步，仿真，膝盖 ×2.05）：
- 后退：-0.09 ~ -0.11 m/s（摩擦 1.0），-0.04 ~ -0.05（0.35），-0.19 ~ -0.21（2.0）；
- 横移 6 场全部正常，没有摔倒；
- 随机条件抽检（重心、摩擦、舵机硬度、推一下）：重心不比实测更靠后时 338 场 0 摔。

## 真机上的教训

- **模型必须和硬件一致。** od20~od25 是按 STS3046 膝盖（力气 ×2.05）练的。在还装着原装 STS3215 膝盖的真鸭上跑 od25：一迈步左右晃 20~50°，摔倒。仿真里拿原装膝盖测 od25 是不摔的，**这个仿真测试不可靠**。
- 反过来，按原装膝盖练的 od17 换上更强的膝盖，仿真里没问题。但真机上只换了一边膝盖时，因为同样的 kp 下新舵机硬一倍，**走路一直往左偏**。
- 所以横移、后退要等两边膝盖都换成 STS3046，用 od25 这一系列再上真机。

## 代码

奖励函数：[`training/openduck_side_reward.py`](../training/openduck_side_reward.py)

接到 mjlab 的 velocity 环境配置里：

```python
from mjlab_microduck.tasks.openduck_side_reward import FEET as SIDE_FEET, side_step_technique, back_step_technique

cfg.rewards["side_step_technique"] = RewardTermCfg(
    func=side_step_technique, weight=1.0,
    params={"sensor_name": "feet_ground_contact", "command_name": "twist", "asset_cfg": SIDE_FEET})
cfg.rewards["back_step_technique"] = RewardTermCfg(
    func=back_step_technique, weight=1.0,
    params={"sensor_name": "feet_ground_contact", "command_name": "twist", "asset_cfg": SIDE_FEET})
```

注意：`asset_cfg` 必须写进 `params`，否则脚的 site_ids 解析不出来。

## 经验

1. 奖励只说"要什么结果"（速度跟上）时，策略容易找到"原地不动也不太亏"的捷径；**直接奖励"怎么做"**（摆动脚往哪挪、挪多少）更有效。
2. 要领只给方向和大概幅度，不给具体关节角度，让策略自己适应真实机器人。
3. 一次只加一条要领、每 1000 步考一次，好坏一眼就能看出来。
