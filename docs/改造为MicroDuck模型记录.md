# 把 Open Duck Mini v2 改用 Microduck 训练方法的记录

这份记录写的是：把 2.1 kg 的 Open Duck Mini v2，从官方 Playground 模型换成 [microduck_rl](https://github.com/pollen-robotics/microduck_rl)（mjlab + MuJoCo Warp + BAM 舵机模型）的训练方法，途中遇到的全部问题和解决办法。

硬件：树莓派 Zero 2W，14 个 STS3215，独立 BNO055，US-100 超声波，2S 4000 mAh 电池。

结论先放前面：

| 项目 | 状态 |
| --- | --- |
| 站立 | 完成，od11 真机站立陀螺仪抖动约 0.001 rad/s |
| 前进 | 完成，步频约 3 Hz，单次连续走过约 75 秒 |
| 转向 | 大体可用，靠闭环；**左转仍明显弱，未解决** |
| 超声波避障 | **效果不好，未解决** |
| 蹲下 / 站起 | 模拟通过，真机地面抖动且蹲不深，**未解决** |
| 语音控制 | 完成（小智 + MCP），语音「停」延迟太大，不能当急停 |

## 1. 迁移方法

- 新任务 `Mjlab-Velocity-Flat-OpenDuck`：沿用 Microduck 的奖励配方，换成 Open Duck 的模型、初始姿态和舵机。14 个关节名字相同，任务代码可以共用。
- 舵机用 BAM 的 STS3215 7.4 V 参数（kp 固件值腿 20、头 8）。
- 观测 61 维：陀螺仪 3、关节位置减 HOME 14、关节速度 14、上一次动作 14、指令 3、重力方向 3、头部指令 4、身体指令 6。
- 动作：目标位置 = HOME + 动作，归一化写进 ONNX。
- Pi 上 `mjlab_walk.py` 按 ONNX 输入维度判断模型类型，同时支持老的 101 维模型和新的 61 维模型。
- 训练约 6 秒一轮，1000 轮约 1 小时 50 分。每轮只改一项，每 1000 轮检查一次。

## 2. 训练迭代（每轮只改一项）

| 版本 | 改动 | 结果 |
| --- | --- | --- |
| od1 | 初版 | 模拟可走；真机在支架上膝盖折叠：策略把膝盖压到 XML 硬限位上 |
| od2 | 目标裁剪到限位 | 不迈步，腿撑在限位上 |
| od3 | 裁剪到 HOME 周围的安全框，加超界惩罚 | 模拟正常；真机地面起步发散摔倒 |
| od4 | 同时改四项（反例） | 不迈步，说明不能一次改多项 |
| od5 | 放慢步频 | 能走，但没解决地面摔倒 |
| od6 | 陀螺仪和加速度延迟 2～5 步 | 找到真机摔倒的主因 |
| od7 | 延迟 0～5 步 | 兼顾低延迟站立 |
| od8 | 舵机 kp 随机 0.75～1.3 | 首次真机站立和行走，但一直抖 |
| od9 | 陀螺仪噪声 ±0.1 | 抖动没改善，这条路无效 |
| od10 | 模型重心后移 12 mm | 走路明显变好（前进 0.144），站立抖动变大 |
| od11 | 动作变化惩罚加倍 | **最终模型 13000 轮**：站立抖动消失，膝盖超界 6～9% |

注意：同一轮训练中，好坏不随轮数单调变化。od11 13000 之后抖动又回升，所以要逐个存档比较，不要只用最后一个。

## 3. 问题与解决

### 3.1 真机摔倒的根因：IMU 延迟

现象：模拟怎么测都不倒，真机一放地上就发散，1～4 秒内摔倒。

排查：把真机发出的目标开环回放进模拟，关节和真机完全对齐，但陀螺仪要平移 3～4 步才对得上。这一步证明了问题在 IMU 延迟，而不是舵机。

解决：训练时给 IMU 观测加 0～5 步随机延迟。后来用单次脚踝阶跃测得干净数据下约 2 步（40 ms），改进读取线程没有明显收益，所以保留原读取程序。

### 3.2 膝盖折叠

现象：od1 在支架上膝盖折到约 1.94 rad。

原因：模拟里 ±1.57 的硬限位替它承重，策略学会了压限位。

解决：模拟限位放到真机极限 2.4，用目标裁剪框代替，并加超界惩罚。Pi 上用同一个框。

### 3.3 站立抖动

现象：od8 站着一直以 3.7 Hz、19 Hz 抖，手碰一下就停，有时自己停。这是策略、舵机、身体、陀螺仪组成的自激振荡。

无效的办法：加大陀螺仪噪声（od9）。

有效的办法：动作变化惩罚加倍（od11）。

判断指标：用「模拟里每步目标变化量」比较。模拟加 ±0.1 陀螺仪噪声才能复现，但数值只能比较，不能当真机预测。蹲下模型模拟 0.6°，真机 1.2°。

### 3.4 重心

用「站在地上做脚踝阶跃」的日志回放，模拟的后仰比真机大一倍。试过脚底软硬、kp、结构弹性都不对，最后是模型重心后移约 12 mm 加 1° 齿轮间隙才对上。

坑：`head_assembly` 的 ipos 改了不生效（它的惯性来自 geom），第一次只移动了 8.2 mm。改完要打印整机重心验证。

### 3.5 舵机限速留在内存里（踩过的大坑）

现象：所有模型突然都走不动，只小幅踏步，身体很稳。

原因：测试脚本写过 goal speed = 300（约 26°/秒），这个值留在舵机内存里，重启服务也不清除，走路程序不会改写。膝盖实际速度正好贴着 28°/秒。

解决：工具用完清零，走路异常时先读寄存器 44、46。这次限速让抖动也消失了，差点误判模型变好。

### 3.6 IMU 冻结

现象：硬着地后 I2C 报错约 1000 次，读取线程卡死，数据不再变化，摔倒保护把站着的鸭子卸力。

解决：
- 改走线，避开右髋转动范围（真正原因之一）。
- 看门狗：0.2 秒数据不变就暂停，保持力矩。
- 摔倒判断只用新数据。

### 3.7 走动中暂停会摔

原因：暂停是立刻停策略，把腿锁在迈步姿势。

解决：软暂停。走动中按暂停先让模型继续站稳 2.5 秒，再锁定。

### 3.8 转向左右不对称（未完全解决）

现象：左右偏差大，而且同一块地面上，下午偏左、晚上偏右。

试过的办法：
- 固定修正 −0.2、−0.1、−0.05：都不合适，转速和指令不成比例。
- 闭环转向：用低通后的陀螺仪积分修正转向指令。左右都到约 13°/秒。

现状：左转指令已接近上限（+0.9），实际还是偏弱，真机下午实测也是左转明显差。

新线索：模拟里给单个关节加 3° 零位误差，走直线的偏转变化如下（基准 −1°/秒）：

| 关节 | +3° | −3° |
| --- | --- | --- |
| 左髋俯仰 | +4.4 | −2.6 |
| 左膝 | +3.3 | −1.6 |
| 左踝 | +3.9 | −1.5 |
| 右髋俯仰 | +3.2 | −4.4 |
| 右膝 | −3.1 | +0.4 |
| 右踝 | −5.0 | +2.9 |
| 髋偏航、髋侧摆 | 基本不变 | 基本不变 |

真机右偏约 −5～−7°/秒，和 3° 左右的俯仰链零位误差同量级，所以下一步是重新校准腿的俯仰、膝、踝零位，尤其是右踝。这只是模拟推断，还没在真机上验证。

### 3.9 超声波（未解决）

- 近距离有 20～26 cm 的假读数，中位数被它带偏；改用窗口内第二小值判断停止。
- 真实避障效果仍不好，要继续查。

### 3.10 手机页面和测试

- 走动中要按「停下」，不是「暂停」。
- 全套路线测试脚本 `tools/duck_test_suite.py` 走 HTTP，每 0.2 秒刷新指令，电脑或 Wi-Fi 断开时舵机服务 0.5 秒内自动停。
- 瞬间压降会触发低电报警，要持续 3 秒才算。
- 人手碰过的日志不能当干净数据，一定要记下来。

## 4. 蹲下 / 站起

- Microduck 的 SitStand 任务移植到 `Mjlab-SitStand-Flat-OpenDuck`。
- 观测顺序和走路不同：重力在陀螺仪后面。我们用错过一次，模型 1 秒就翻。
- 跪坐姿势（小腿着地）3000 轮学不会站起：普通插值起身要 1.9 N·m，还会后翻。
- 改成脚掌贴地的深蹲，1000 轮就能蹲下再站起，但模拟里只下降约 2.8 cm。
- 真机：悬空时抖 8～10°/步（模拟吊起来也一样，这是正常的）。地面上仍然抖（陀螺仪约 0.08），蹲得很浅。
- sit3 把动作变化惩罚再加倍，结果待真机验证。

sit3 模拟结果：第 5000 轮在 kp 20、25 都能蹲下站起，模拟抖动约 0.5°/步，是下一个真机候选。蹲下幅度仍只有约 2.5 cm，这是姿势决定的，要蹲得明显，得改目标姿势。

### 头部抬头低头

两个舵机都能抬头低头，但程序只把指令发给 `head_pitch`，`neck_pitch` 一直是 0，所以看起来脖子不动。已改成两个舵机分担。两者正方向相同，改完要真机验证平衡。

## 5. 语音（小智）

- 微雪 ESP32-S3-AUDIO-Board，刷 v2.4.0，走小智云端。
- Pi 跑 `xiaozhi_bridge.py`，主动连接小智 MCP 接入点，把工具调用转发给 `/cmd`，家里不用开放端口。接入点地址等于钥匙，只放 Pi 上的私有文件，不要进仓库。
- 只开放安全工具：停、走（最多 5 秒）、转（最多 90°）、查状态、关机。上力、开始、卸力不开放。
- 工具确认不要用布尔参数：大模型不填，要拆成两个工具。
- 语音到动作延迟可达十几秒，语音「停」不能当急停。
- 自改固件：`xiaozhi/` 里的补丁。加了倒计时（到点由云端说一句）、多条本地唤醒词、本地「停下」直发 Pi。提醒文本要短，长文本云端会拒收。

## 6. 给后来者的建议

1. 每次只改一个参数。
2. 模拟不复现真机现象时，先用开环回放定位是哪一段不一样。
3. 动手前先读寄存器，别被残留状态骗。
4. 看数据要和好的基准比，不要和更差的比。
5. 改打印件位置或重量后，重新测重心。
6. 逐个存档比较，最后一个不一定最好。
