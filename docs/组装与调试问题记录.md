## 准备与软件环境

最大的障碍是网络：树莓派连不上 GitHub，所有代码都先在电脑上下载再传过去。

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| 树莓派拉不上 GitHub 代码 | 国内网络连接被重置 | 电脑下载后用 scp 传到树莓派；pip 用清华镜像 |
| duckpi.local 找不到树莓派 | 电脑不支持 mDNS | 直接用 IP 192.168.50.139；变了就在 ARP 表里找 MAC 88-A2-9E 开头的 |
| 运行脚本报“找不到 numpy” | 没激活虚拟环境 | 先 `source ~/.virtualenvs/open-duck-mini-runtime/bin/activate` |
| cv2 导入失败 | 缺系统库 | `apt install libgl1` |
| 训练时显存不够 | RTX 4060 笔记本只有 8 GB | 并行环境数强制设为 512，1.6 亿步约 1 小时 50 分 |
| 官方运行时没有“站立”脚本 | 官方只提供走路 | 自己写了 v2\_rl\_stand.py，配自训的站立模型 |
| 卖家没有黑马外壳专用模型 | 黑马课程只是跑官方训练 | 用官方模型，再自己按真机重新训练 |
| 卖家说 Pi Zero 要配转接板才支持 | 黑马用的是 KickPi 主板 | 选“路线 A”：Pi Zero 2W 按官方方式直接接线，只用黑马的电源板和脚底板 |

## 舵机与舵机板

舵机本身都没坏，出问题的是一块舵机板和一根舵机线；关键习惯是插拔舵机线前先断舵机电源。

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| FD 软件（1.9.8.2）没有“中位校准”按钮 | 软件版本差异 | 写了 set\_middle.py：地址 40 写 128，当前位置变成 2048 |
| 新舵机最大输入电压是 80（8.0 V） | 出厂设置；满电 8.4 V 时会保护不动 | 每个舵机设 ID 时顺便改成 90 |
| 舵机板搜不到任何舵机，空载也收到固定乱码 | 舵机板总线端损坏，推测是带电热插拔 | 换新的 Waveshare 板；之后插拔前先断舵机电源 |
| 跳线位置不确定 | 你的板子 USB 控制是 B 位（我一开始说成 A） | 保持 B |
| 换板后脚本连不上 | 旧板 COM3，新板 COM4 | 脚本参数改 COM4；在树莓派上是 /dev/ttyACM0 |
| 12/13/14 突然找不到，新 14 号闪红灯 | 一根舵机线断了 | 换线；舵机线用 5264-3P，不用杜邦线 |
| 舵机板只有 2 个接口 | 官方是右腿、左腿、脖子三条链 | 脖子链接在左腿末端（和官方接线图一致） |
| 走路时偶尔出现校验错误，都是 ID 10 | ID 10 的舵盘松了 | 拧紧后零位没变（+0.9°）；官方对偶发校验错误的态度是“可以忽略” |

## 机械组装

最省事的办法是“舵盘随便哪个齿装上，装完再用软件校准零位”；最要紧的是螺丝不能松。

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| 舵盘对齿很难，反复拆装 | 25 齿，每齿约 14°，很难正好对上 | 不再对齿：装好后摆成零位姿态，用 set\_middle.py 校准 |
| 舵盘方向搞不清 | 我一度把副舵盘方向说反了 | 两个舵盘都是凸台朝舵机、平面朝外 |
| 大多数关节只拧了 2 颗舵盘螺丝 | 调试阶段图快 | ID 10 因此松动，走路变乱；要把 4 颗装齐，并定期检查 |
| 要不要上螺纹胶 | 社区建议走路前上蓝胶 | 整机调完再上，只涂在铝舵盘螺丝；不能沾到打印件（会腐蚀塑料）和舵机轴 |
| 头部横滚（33）方向和仿真相反 | 整个头板装反了 180° | 头板转回来（宽端朝前），取消软件里的反向补丁，重新校准 32、33 |
| 头部 4 个舵机偏差很大（最大 156°） | 头部从没校准过 | 以“脖子竖直、头板水平朝前”为零位校准 30–33 |
| 右髋横滚（11）偏 55° | 加固时舵盘重新装过 | 重新校准 |
| 躯干底部轴承漏装 | 步骤遗漏 | 加固时压入 2 个 6804 轴承和盖子 |
| 红色支架用途搞错 | 我一开始当成了身体框架 | 它是黑马的展示支架，用来悬空测试 |
| 树莓派、舵机板放哪 | 黑马结构和官方不同 | 舵机板拧在躯干顶板 4 个螺柱上，树莓派放身体底部，SD 卡朝可拆盖板 |

常用的关节方向（+0.3 rad）：右髋俯仰 12 → 腿向后摆，左髋俯仰 22 → 腿向前摆；膝盖 13/23 → 小腿向前；脚踝 14/24 → 脚尖抬起。全部 14 个关节已经和仿真对过，不需要软件反向。

## 电源

唯一一次冒烟是用杜邦线接电源；之后电源全部用 XH 线 + WAGO，树莓派由 UBEC 供电一直稳定，没有欠压记录。

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| 电源板到 UBEC 的杜邦线冒烟、熔化 | 杜邦线太细且短路 | 电源绝不用杜邦线；用剪开的 XH 线 + WAGO 接线端子；事后测过电池和电源板都正常 |
| 树莓派的 5 V 从哪里来 | 黑马电源板没有 5 V 输出 | Hobbywing 3A UBEC（跳线 5 V），插在树莓派 2/4/6 脚：红 → 4，黑 → 6，空位在 2；上机前先测空载 5.3 V |
| 舵机板怎么供电 | 不想再买 DC 插头 | 舵机板旁边有 DC+/DC− 绿色端子，电源板输出用剪开的 XH 线接过去 |
| 树莓派只有一个 USB 口 | Pi Zero 2W 的限制 | 30 cm Type-C ↔ Micro OTG 线接舵机板；以后加麦克风要用 I2S 或 Hub |
| 充电器指示灯一直不变绿 | 指示灯不准 | 以电压为准：8.4 V 是满电，大约充 2 小时 |
| 电池快没电时没有提示 | 树莓派没有电压检测 | 14 个舵机最低电压设成 7.0 V（低于会闪红灯）；后台服务 battery-guard 每 30 秒读舵机电压：低于 7.2 V 绿灯快闪，连续 3 次低于 6.8 V 自动卸力并关机 |
| 直接关电源怕损坏 SD 卡 | 系统一直在写文件 | 先双击 关闭鸭子.bat，等绿灯熄灭再关开关 |

社区提醒：BMS 最好用 20 A 的（10 A 的有人遇到大电流时断电），电池到舵机板至少 18 AWG 线。我们的 BMS 是 10 A，目前还没出问题，留意即可。

## IMU 与脚开关

IMU 的 I2C 毛刺是站不住的第一个真正原因：换成软件 I2C 后毛刺从 25% 降到 0%，鸭子第一次独立站住 30 秒。

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| IMU 读数偶发巨大跳变，像鸭子突然后仰 7° | 树莓派硬件 I2C 和 BNO055 的“时钟拉伸”不兼容，约 25% 的读数第一个字节最高位被翻转 | /boot/firmware/config.txt 关掉硬件 I2C，改用同一对引脚的软件 I2C（i2c-gpio）；毛刺 0%，读取 104 Hz |
| 校准是在毛刺总线上做的 | 先校准、后发现毛刺 | 修好后重新校准：平放六个面各静止 5 秒，再画 8 字 |
| IMU 方向是否正确 | 社区里最常见的坑（装反、x/y 对调） | 实测低头时 x 为负、右侧朝下时 y 为正，和仿真一致（x 前、y 左、z 上），upside\_down=false |
| 脚开关线不够长、接头不对 | 黑马脚板是 XH 接口 | 在身体端剪断，用 WAGO 接母头杜邦线；左脚 15+20，右脚 13+14；实测左、右、双脚都正确 |
| i2cdetect 命令找不到 | 不在 PATH 里 | 用全路径 /usr/sbin/i2cdetect，IMU 地址 0x28 |

引脚汇总：IMU VCC 1、SDA 3、SCL 5、GND 9；UBEC 4（5 V）和 6（GND）；左脚 15+20；右脚 13+14。

## 软件与运行时的坑

这些问题不会报错，只会让现象变得奇怪，所以最费时间。

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| 膝盖像“卡”在 52° 走不到初始姿态 | 我写的调试工具往舵机写了目标速度（地址 46），断电前一直有效 | 用过工具后运行 clear\_speed.py，把地址 46/44 清零 |
| 自训站立模型站姿外八、脚底翻边 | 模型本身学得不好 | 改用官方走路模型，速度为 0 时就是站立 |
| 按 p 后鸭子定格在半步姿势 | p 是暂停，电机锁在最后位置 | 走路中想停用空格（速度归零、继续平衡） |
| 带 --log 也没存下数据 | 我的脚本 bug，保存那段没写进去 | 已修，现在默认就记录 |
| 按 x 没反应，脚本还在跑 | 终端窗口没有焦点 | 先点一下终端再按 |
| 运行时的 --pitch\_bias 参数不起作用 | 代码里存了却从没用到 | 不用它；仿真实验证明 ±8° 的 IMU 角度偏差不影响官方模型 |
| 加速度计 +1.3 偏置不一致的疑问 | 训练代码那行没生效，只有仿真推理脚本加了 | 我们的运行时没加，和训练一致，不用改 |
| 远程用 pkill 结束脚本，后面的命令没跑 | pkill -f 把自己这条命令也匹配杀掉了 | 写成 `pkill -f "[w]alk_zero"` |
| 官方说偶发校验错误可忽略 | 运行时会丢掉这一帧 | 只在频繁时查线和松动 |

## 站立与行走调试

走不稳的主因是**舵机反应太慢**：出厂的加速度限制让舵机比仿真慢 3 倍，改掉后再把刚度 P 从 30 降到 20，鸭子就能稳定行走。每一步都用 `--log` 数据和仿真对比确认，一次只改一个变量。

| 顺序 | 现象 | 查出的原因 | 解决 | 效果 |
| --- | --- | --- | --- | --- |
| 1 | 站立时反复向后倒 | IMU 的 I2C 毛刺（不是重量：整机 2085 g，仿真 2107 g） | 软件 I2C + 重新校准 | 第一次独立站 30 秒 |
| 2 | 走几步就乱 | ID 10（右髋偏航）松动 | 拧紧，零位没变 | 校验错误消失 |
| 3 | 200 秒摔 5 次，几乎都向后；走路前后晃 ±10–14° | 舵机跟踪滞后 200 ms（仿真 60 ms），寄存器 85（最大加速度）出厂值 50 限制了加速 | 14 个舵机寄存器 85 改成 0（先备份） | 悬空滞后 160 → 80 ms，跟踪误差降到 1/5 |
| 4 | 地上“发冷打颤” | 舵机变快后控制回路 5 Hz 振荡 | 腿部 P 30 → 20（试过加阻尼 D=8，无效） | 不打颤，走路晃动 ±4° |
| 5 | 速度 0.05 时不迈步 | 官方训练奖励有“死区” | 走路用 0.1（w 按两次） | 每只脚每秒迈步 1.4 次（原来 0.3 次） |
| 6 | 一直向右偏，每秒约 12° | 左右不对称，而且偏的方向每次不同 | 先加固定微调 0.1，再加陀螺仪自动保持方向 | 方向偏离 ±10–18°，走完只差 ±3° |
| 7 | 摔倒后舵机趴在地上硬顶 | 运行时没有保护 | 倾斜超过 40° 自动卸力，按 r 恢复 | 真机验证通过 |
| 8 | 后退 2.6 秒就向后摔 | 官方模型没学会后退（仿真里它干脆不动） | 暂不用 s；重新训练 | 未解决 |
| 9 | 单独横移 0.1 不动 | 训练奖励的横向 0.1 死区 | 和前进一起用，或横移用 0.2 | 重新训练会修 |

调整前后对比（地面、前进 0.1）：

| 指标 | 上午（原始设置） | 下午（现在） | 仿真参考 |
| --- | --- | --- | --- |
| 舵机跟踪滞后 | 200 ms | 80 ms | 60 ms |
| 走路前后晃动（标准差） | 10–14° | 4–5° | 2° |
| 每只脚每秒落地 | 0.3 次 | 1.4 次 | 0.6–2 次 |
| 摔倒 | 200 秒 5 次 | 26 秒和 50 秒各一段，0 次 | 0 |

顺带排除的怀疑：IMU 装歪（仿真里 ±8° 都不摔）、脚开关信号（双脚着地比例 80% 和仿真 81% 一致）、加速度偏置、丢帧（一直是 0）。

双击 `D:\Claude\duck\鸭子走路.bat` 就会用最佳设置启动；关机双击 `关闭鸭子.bat`。

| 设置 | 值 | 在哪里 |
| --- | --- | --- |
| 舵机寄存器 85（最大加速度） | 0（出厂 50） | 已写进 14 个舵机，断电保留；备份在 pi/backup\_2026-10-25/servo\_regs\_factory.json |


电量：满电 8.4 V；约 7.3 V 就停止走路测试去充电。

## 未解决的问题与下一步

剩下的问题大多是官方模型本身的局限，正在用“真机版”参数重新训练（1.6 亿步，约 2 小时）。

- 后退会摔；单独横移 0.1 不动；速度为 0 时会原地踩。
- 走路时左右摇摆偏大，横滚最大约 25–30°，还没因此摔，但要盯着。
- 跑偏的根本原因还没查（现在靠陀螺仪自动修正）；站立时右髋偏航 ID 10 常保持 +5.5°，左边只有 −2.3°。
- 大部分关节仍只有 2 颗舵盘螺丝。

重新训练做了哪些改动（仿真已先校准：真机版仿真的舵机滞后 90 ms，真机 80 ms）：

1. 舵机刚度按真机 P=20、头部 P=8 换算；最大力矩 2.0 N·m（原来 3.23），并在 1.6–2.2 之间随机。
2. 速度奖励去掉横向 0.1 死区、变得更严格，小速度也值得迈步。
3. 速度为 0 的比例 10% → 20%，“站着别动”的惩罚加强，让它学会真正站立。
4. 每 10 秒换一个指令，学会起步、停下、变向。

- [ ] 整机调好后：舵盘螺丝装齐 4 颗并上螺纹胶
