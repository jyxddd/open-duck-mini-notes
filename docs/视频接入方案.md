# 视频接入方案

状态：方案，尚未实施。标注「待验证」的地方没有在这台鸭子上测过。

## 两条路

| | A. 语音板摄像头 | B. 树莓派摄像头 |
| --- | --- | --- |
| 硬件 | ESP32-S3-AUDIO-Board 的 CAMERA 接口 | Pi Zero 2W 的 CSI 接口 |
| 模块 | OV2640 或 OV5640 | Camera Module 3，或 AI Camera（IMX500） |
| 软件 | 小智固件已有 `self.camera.take_photo` | 自己写 |
| 看什么 | 单张照片，由云端大模型描述 | 连续视频，本地处理 |
| 延迟 | 几秒到十几秒 | 普通摄像头视算法而定；AI Camera 在相机内推理 |
| 适合 | 「前面是什么」「帮我看看」 | 跟随、识别、躲避 |
| 不适合 | 实时控制 | 没有云端大模型的问答 |

固件启动日志里能看到它在探测 OV2640 和 OV5640（没接摄像头所以报错），说明这两款在代码里是打开的。接口针数和具体模块要对照板子再买，这一点待验证。

## 建议分两步

### 第一步：语音板拍照（便宜、改动最小）

1. 买一个与板子接口匹配的 OV2640 或 OV5640 模块，先在桌面上接好。
2. 说「帮我看看前面是什么」，确认云端调用拍照并描述。
3. 决定安装位置。语音板在胸前，摄像头也要朝前，线不穿脖子。

### 第二步：树莓派 AI Camera（要实时功能时再做）

- Pi Zero 2W 算力紧张，还要跑 50 Hz 控制，不能把视觉放在 CPU 上。AI Camera 在相机里推理，这正是选它的原因。
- 需要 Zero 的窄口转接线。
- 相机装在头上可以跟着转头；线要穿脖子，留够余量。
- 控制循环不能被视觉拖慢，要放在单独进程，只把结果交给 `duck_server`。

## 能做的应用（按实用排序）

| 应用 | 需要 | 说明 |
| --- | --- | --- |
| 语音问「看到了什么」 | A | 云端描述，最快做到 |
| 手机看鸭子视角 | B | Pi 把画面推到手机页面 |
| 看到人就抬头、转头 | B | 头部舵机跟踪，不走路，安全 |
| 听到名字转向说话的人 | B + 语音 | 表演效果好 |
| 跟着人走 | B | 需要转向和避障先可靠 |
| 视觉避障 | B | 补超声波的不足，难度高 |
| 识别充电座或标记 | B | 远期 |

## 风险

- 隐私：A 方案的照片会上传到云端服务；在家里要明确什么时候拍。
- 算力和发热：Pi 上的视觉会抢占控制循环。
- 走路震动：走动中画面抖，识别效果要实测。
- 重量和重心：加摄像头后要重新测重心。
